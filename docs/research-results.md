# 审核自动化研究成果汇总

> 日期：2026-05-22  
> 范围：嘉惠多多非发券 3C、国补家电数码 3C/家电首期自动通过链路  
> 结论：优先建设本机审核服务，影刀首期闭环，Playwright 保留迁移路线

## 1. 核心判断

当前项目最稳妥的落地方式不是让自动化工具直接写死业务规则，而是把业务判断集中在本机 Python 审核服务中。影刀或 Playwright 只负责页面采集、图片下载、调用本机接口和点击按钮。

这样做的原因：

- 审核规则可以被单元测试覆盖，不依赖某个网页自动化工具。
- 影刀首期上手快，适合尽快验证真实页面闭环。
- Playwright 可作为后续替代手脚层，迁移时复用同一个 JSON 契约。
- 敏感图片、身份证、订单字段不外传，云 OCR、Dify/扣子等云端链路不进入生产审核。
- 系统只自动通过高置信合格单，不自动驳回；不确定、异常、超时统一转人工。

## 2. 首期业务边界

首期只覆盖标准程度较高的订单：

- 非发券 3C：页面字段完整、身份证姓名和有效期高置信通过、商品或激活图 SN 明确匹配、图片无强风险。
- 国补 3C：动态识别品类，不沿用上一单类别；SN 必须在相关图片中明确匹配。
- 国补家电：除 SN 和图片风险外，收货地址必须达到小范围粒度，例如小区、路号、栋、单元、室、门牌、村组。

以下情况统一进入人工：

- 页面字段不完整。
- 品类不在首期支持范围。
- SN 未识别、疑似冲突或置信不足。
- 身份证 OCR、有效期、姓名匹配无法高置信通过。
- 图片存在截图、网图、拼图、P 图、非实拍强风险。
- 家电地址只到省市区县、乡镇、街道，或只到村但没有组/门牌。
- 汽车审核、历史驳回重提、疑似资料篡改。
- 服务异常或单单超过 60 秒。

## 3. 技术路线

推荐架构：

```text
网页审核后台
  -> 影刀首期 / Playwright 备选
  -> 本机临时图片目录
  -> 本地审核服务 http://127.0.0.1:8765/audit
  -> pass / manual / error
  -> 点击通过 / 下一单 / 暂停
```

本地服务要求：

- 只绑定 `127.0.0.1`，禁止监听 `0.0.0.0`。
- 通过 `X-Audit-Token` 做本机调用鉴权。
- 单单最大审核预算 60 秒。
- 对外决策只返回 `pass`、`manual`、`error`；旧的 `skip` 语义只允许内部兼容，对外统一成 `manual`。
- 日志和 CSV 报表只记录订单号、场景、决策、原因、耗时、关键布尔证据，不记录图片 URL、OCR 原文、身份证号、手机号、完整地址。

## 4. 已形成的工程成果

当前仓库已经形成以下工程方向：

- `audit_service.py`：本机 FastAPI 审核服务入口，提供 `/health` 和 `/audit`。
- `modules/audit_models.py`：统一请求、响应和决策归一化。
- `modules/audit_runner.py`：服务化审核编排，负责品类、图片角色、OCR、SN、地址、鉴伪和超时控制。
- `modules/page_parser.py`：从页面大段文本中提取订单号、姓名、SN、地址、品类等字段。
- `docs/yingdao-integration-contract.md`：影刀接入本机服务的 JSON 契约。
- `docs/superpowers/specs/2026-05-21-audit-automation-integrated-design.md`：完整方案设计。
- `docs/superpowers/plans/2026-05-21-audit-automation-integrated-plan.md`：实现计划。

## 5. 关键研究结论

1. OCR 只能识别文字，不能真正理解“这是不是商品”。首期必须用页面标题、商品字段、图片角色、SN OCR、鉴伪结果组合成证据链。
2. 当前硬件为 CPU 路线，PaddleOCR 和图像鉴伪速度存在上限，不能承诺 700 单稳定 1 小时内完成。
3. 快路径应优先处理标准单，目标 10-25 秒/单；慢路径只处理仍有希望自动通过的订单，必须受 60 秒上限约束。
4. 自动通过率需要通过 3 天以上试运行测真实基线，首期目标可放在 70%-85%，但应以误通过为零作为优先目标。
5. 影刀适合首期验证，但不应承载业务规则；迁移到 Playwright 时，只替换页面采集和点击层。

## 6. 下一步建议

1. 跑通本机服务和现有测试，确认 JSON 契约稳定。
2. 用影刀接入观察模式：只采集、调用、记录，不点击通过。
3. 连续抽查自动通过候选单，确认没有误通过后再开启自动点击通过。
4. 记录每天的通过率、耗时、转人工原因分布，用数据决定下一轮优化。
5. 当影刀稳定性、费用或安全配置不能满足要求时，按迁移指南切换到 Playwright。
