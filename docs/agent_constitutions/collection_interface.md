# 采集接口分宪法

## 1. 职责
采集接口只负责两件事：按用户给出的自然语言或页面条件采集订单审核所需字段；在订单审核结果产生后，按受控结果执行页面反馈动作。

## 2. 边界
不负责预检、SN 比对、合规判断、图片真实性、报告生成。不得采集审核不需要的字段，不得把页面规则改写成审核规则。

## 3. 采集规则
- 只采集审核链路需要的字段和图片
- 优先复用安全登录状态，避免让用户重复登录
- 用户只需给出采集条件，系统应尽量自动定位相关订单
- 页面、权限、登录、字段含义不确定时，停下汇报，不猜

## 4. 页面反馈
认领订单和点击通过属于最后一步，只能在 `off / shadow / enforce` 开关下实现。未获总负责人确认上线前，不得 `enforce`，不得真实点击通过。

## 5. 验收
- 采集字段不超范围
- 登录状态复用有效
- 条件采集可追溯
- shadow 下页面反馈不产生真实动作
- enforce 前必须经总负责人验收
