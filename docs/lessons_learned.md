# Lessons Learned

本文件记录项目执行过程中已经解决的问题、原因和后续规避方式。后续任务开始前必须先读取本文件。

## 2026-08-05 合规模型的分组答卷必须按输入边界裁决

问题：同一次多图片合规调用中，模型可能把激活/SN图片的 `image_id` 误写入拆封证据数组。若把额外组ID当成拆封证据参与业务裁决，会让本来完整的拆封/安装证据被误拒；若静默接受缺失或重复的真实拆封组ID，又会产生误放风险。

规避：本地安全门只裁决输入中明确属于拆封/安装组的ID。正式入口和缓存校验必须把原始ID直接传给validator，不得先字符串化或过滤空值。仅当全部预期拆封ID存在、唯一且字段类型完整时，机械丢弃额外的非拆封组ID并记录修正；预期ID缺失、重复或类型错误继续按结构异常转人工。结构异常原因码必须保持为 `MODEL_UNCERTAIN`，不得被后续业务兜底改写。

## 2026-07-30 分宪法必须落盘

问题：分宪法只在总负责人会话中定稿但未写入文件时，分支 Agent 只能读到 `AGENTS.md`，会回执 `MISSING_SUB_CONSTITUTION`，无法按模块边界执行。

规避：凡要求分支读取的规则，必须写入独立文件，并在 `AGENTS.md` 标明路径。分支只读取总宪法和自己的分宪法，不读取其他模块分宪法。

## 2026-07-30 跨会话工具调用回执

问题：给分支发送任务后，应使用线程工具读取回执；无关 MCP 资源读取不到 Codex 任务状态，容易浪费步骤。

规避：跨会话协调使用 `send_message_to_thread`、`wait_threads`、`read_thread`。工具调用类踩坑只要会影响后续项目协作、测试或验收，就记录到本文件；一次性、无复用价值的小失误不必记录。

## 2026-07-30 分支回执必须进入总负责人汇报队列

问题：分支任务完成并返回回执后，如果总负责人没有立即读取并汇报，会造成用户看不到已完成成果，违反“任一分支任务完成后立即按三项格式汇报”的要求。

规避：每次派发分支任务后，必须把该分支加入待回执队列。总负责人在派发新任务、回复用户或结束当前轮次前，必须先用 `wait_threads` 或 `read_thread` 检查待回执队列；发现完成回执后立即验收并按三项格式汇报。不得因为切换到其他任务而漏报已完成回执。

## 2026-07-30 总负责人线程工具入口必须固定

问题：跨线程协作时，如果总负责人没有固定使用 Codex 线程工具，而是在 `navigate_to_codex_page`、shell 占位命令、MCP resource 工具之间反复尝试，会出现行动卡壳、重复无效调用、回执未及时收取等问题。MCP resource 不是 Codex 线程状态入口，不能用于读取分支回执。

规避：总负责人收发分支任务只允许使用三类线程工具：`send_message_to_thread` 发任务，`wait_threads` 等待回执，`read_thread` 读取指定线程。除非用户明确要求打开界面，不使用 `navigate_to_codex_page` 作为任务协调步骤；不得用 shell `Write-Output` 充当进度或等待；不得调用 MCP resource 读取 Codex 分支状态。若工具入口不可见，先用 `tool_search` 搜索目标工具名，然后立即调用搜索到的线程工具，不得反复试错。

## 2026-07-30 分支任务不得在未确认回执前切换新主线

问题：采集任务和 SN 任务并行时，总负责人未先收齐或明确标记待回执状态，就继续派发新任务，导致 SN 回执没有被及时读取，用户无法判断任务是否完成、卡住或需要追问。

规避：每个已派发任务必须登记为 `等待回执`、`已回执待验收`、`已验收已汇报` 三种状态之一。总负责人在派发第二个任务前，必须明确上一个任务当前状态；同一时间最多并行 3 个分支任务，但每个任务都必须有独立待回执记录。未收到回执时只能汇报“等待回执”，不得表现为已经处理完。

## 2026-07-30 回复前必须执行回执门禁

问题：分支已经返回提交回执后，总负责人先回复用户、后检查待回执队列，导致用户追问“已经回执，为何没有反馈给我”。这说明“待回执队列”只被写成原则，没有形成回复前硬门禁。

规避：总负责人在任何回复用户、结束当前轮次、派发新任务之前，必须先检查是否存在 `等待回执` 或 `已回执待验收` 任务；存在则先用 `wait_threads` 或 `read_thread` 读取并处理，完成验收后立即按三项格式汇报。未执行该门禁，不得向用户发送普通进度回复。

## 2026-07-30 错误工具入口必须立即止损

问题：总负责人在读取分支回执时多次误触 MCP resource。MCP resource 不是 Codex 分支状态入口，连续误触会浪费步骤，并可能再次造成回执延迟。

规避：读取 Codex 分支状态只能使用 `send_message_to_thread`、`wait_threads`、`read_thread`。一旦误调用非线程工具读取分支状态，必须立即停止当前分支协调动作，向用户说明错误和影响；不得继续反复尝试同类错误工具。MCP resource 只用于 MCP 服务器资源，不用于 Codex 任务回执。

## 2026-07-30 模型测试密钥不得反复向用户索取

问题：分支执行真实模型测试时，如果每个会话都临时等待用户复制 API 地址和密钥，会导致 shadow 对比、SN 验收和采集验收反复卡在环境问题上。

规避：模型测试统一通过 `tools/run_with_local_vision_secrets.ps1` 加载本机用户目录中的密钥文件；首次配置或更新时，由总负责人使用 `tools/install_local_vision_secrets_from_clipboard.ps1` 从剪贴板写入 `C:\Users\guoru\.audit_robot\secrets\vision.env`。真实密钥和地址不得写入仓库、日志、报告或回执。分支遇到缺少 `VISION_API_BASE_URL` 或 `VISION_API_KEY` 时，先使用该入口重试，再向总负责人回执是否仍阻塞。

## 2026-07-30 当前终端不是分支回执入口

问题：总负责人检查分支进度时误用 `read_thread_terminal`，该工具只读取当前会话终端，不读取指定分支状态，会造成重复无效动作和回执延迟。

规避：分支状态只使用 `wait_threads` 或 `read_thread`；`read_thread_terminal` 只能用于当前会话本地命令输出，不得用于分支任务回执、进度或状态检查。误触后必须立即停止同类工具调用，改用线程工具。

## 2026-08-10 旧 AUDITING 单没有租约时不能被重复抓取续命

问题：自动审核从旧进程切换到新进程时，可能留下状态为 `AUDITING`、但 `lease_expires_at` 为空的历史订单。若后台列表再次返回同一订单，去重入库逻辑会刷新 `updated_at`；而恢复逻辑只按 `updated_at` 判断是否过期，就会导致这类订单一直被“续命”，无法重新审核或转入终态。

规避：`AUDITING` 恢复不能只看 `updated_at`。只要 `lease_expires_at` 为空、空字符串、已过期，或 `updated_at` 超过兜底超时时间，都允许新进程接管并写入新的租约。回归测试必须覆盖“旧 AUDITING + 无租约 + 重复抓取刷新 updated_at”仍可被接管。

## 2026-08-10 系统 SN 和条码值不得做 O/0 相似字符改写

问题：系统 SN 是审核标准答案，条码值是扫码原文证据；如果在这两类值上执行 O/0 相似字符互换，会把照片或模型读到的不同 SN 误判为一致。

规避：SN 本地比对必须区分系统侧、模型侧和条码侧清洗。系统 SN 只做标签、空白、大小写等非语义规整，保留 `O` 与 `0` 原义；条码值只做控制字符和首尾空白规整，不得做 O/0 互换。
