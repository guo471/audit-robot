# 非实拍识别小样本训练与本地部署设计

日期：2026-07-13

## 1. 目标与边界

使用项目现有图片训练第一版非实拍风险分类器，并建立可持续追加样本、重新训练、评估和本地部署的完整流程。

第一版是离线和影子模型，不接入生产自动放行。模型输出只允许为：

- `low_risk_candidate`：未发现非实拍风险，仅供影子评估。
- `manual_review`：检测到风险、证据不足、模型异常或超时。

模型不得输出正式通过或驳回。缺少权重、权重未验收、图片损坏、预处理失败、推理异常和超时都必须返回 `manual_review`。

## 2. 当前数据事实

- 非实拍样本目录现有 71 个图片文件；已有报告按 SHA-256 去重后得到 69 张唯一非实拍样本。
- 基准清单包含 100 张原流程已通过的实拍候选，但这些不是严格真值。
- 已确认 `S002`、`S034` 为历史拼接图片，`S036` 为外部浏览器页面；三者不能作为合规实拍训练样本。
- 其余实拍候选也需要经过标签清洗，不能仅凭原流程已通过直接作为真值。
- 当前样本量只能训练可行性模型，不能证明跨设备泛化能力或生产漏放率。

## 3. 第一版模型

第一版只使用一个 `MobileNetV3-Large` 二分类模型：

```text
原始图片
  -> 方向校正和 RGB 解码
  -> 保持比例缩放和中心填充
  -> MobileNetV3-Large
  -> non_real_risk 概率
```

选择理由：

- 使用 ImageNet 预训练权重，适合小样本迁移学习。
- 参数量和 CPU 推理成本较低。
- PyTorch 训练后可以导出 ONNX，在无独立显卡的机器上运行。
- 第一版不加入 YOLOX、第二个分类器或外部 VLM 调用，降低部署和维护复杂度。

现有 FFT、边缘均匀度和清晰度指标只记录为诊断特征，不直接覆盖模型结论。后续只有消融实验能证明它们稳定提高锁定集召回时，才加入模型输入或裁决规则。

## 4. 数据清洗与划分

### 4.1 数据清单

所有图片统一写入版本化 CSV 清单，至少包含：

```text
sample_id,path,sha256,label,label_status,source_group,order_id,kind,split
```

字段约束：

- `label` 只能为 `real`、`non_real` 或 `unknown`。
- `label_status` 只能为 `confirmed`、`candidate` 或 `excluded`。
- 只有 `confirmed` 样本可以参与训练和正式评估。
- `source_group` 表示同一源照片或同一订单；同组样本不得跨训练、验证和测试集。

### 4.2 现有数据处理

- 69 张唯一非实拍样本标记为 `non_real/confirmed`。
- `S002`、`S034`、`S036` 从实拍候选中剔除，并按业务定义重新标记。
- 其余实拍候选先标记为 `real/candidate`，经过清洗后才能升级为 `real/confirmed`。
- 文件损坏、重复文件和无法确认的图片标记为 `excluded` 或 `unknown`，不用于训练。

### 4.3 小样本评估

数据划分使用固定随机种子并按 `source_group` 隔离。由于样本很少，采用：

- 一份锁定测试集，至少保留 14 张非实拍和 20 张确认实拍。
- 其余数据用于分组五折交叉验证和最终训练。
- 锁定测试集只在模型和阈值冻结后运行，不能用于调参。

随着新样本增加，旧锁定集永久保留，新设备和新拍摄条件另建增量挑战集。

## 5. 训练方法

第一轮迁移学习分两段：

1. 冻结 MobileNetV3 主干，只训练二分类头。
2. 使用较低学习率解冻最后一到两个阶段，做短轮次微调。

训练使用类别加权交叉熵，避免样本数量差异使模型偏向实拍类别。数据增强只做轻度且对两类对称的变化：亮度、对比度、轻微缩放、轻微透视、轻微模糊和 JPEG 压缩。不使用人工生成摩尔纹代替真实翻拍样本。

每次训练必须保存：

- 数据清单版本和 SHA-256。
- 代码版本、随机种子和训练参数。
- 最佳权重、交叉验证结果和锁定集结果。
- ONNX 文件及其 SHA-256。
- 决策阈值和模型状态。

## 6. 阈值和订单聚合

模型输出 `non_real_risk` 概率。第一版阈值只根据验证集确定，不以降低人工率为目标反向放宽。

单张图片规则：

- 分数达到风险阈值：`manual_review`。
- 分数位于灰区：`manual_review`。
- 只有低于冻结低风险阈值且推理正常：`low_risk_candidate`。

订单规则：三张图片中任意一张为 `manual_review`，整单为 `manual_review`。只有三张均为 `low_risk_candidate`，订单才可输出同名影子候选状态。

新增独立目录，不修改现有审核模块：

```text

  README.md

  requirements-runtime.txt
  configs/
  src/
  scripts/
  models/
  data/
```

命令行工具包括：

- 从现有基准清单建立数据清单。
- 校验、去重和划分数据。
- 训练与交叉验证。
- 评估和阈值冻结。

- 单图和三图推理。

## 8. 环境与依赖

使用独立 Python 3.11 虚拟环境，不修改当前 Python 3.13 环境。

训练端主要依赖：

- PyTorch
- torchvision
- NumPy
- Pillow
- OpenCV
- scikit-learn
- ONNX

运行端主要依赖：

- ONNX Runtime
- NumPy
- Pillow
- OpenCV

第一版可以在当前 CPU 上完成小样本训练验证，但迭代速度不作为承诺。若 CPU 训练耗时不可接受，训练迁移到临时 NVIDIA GPU；ONNX 推理仍在当前电脑完成。

## 9. 稳定性设计

- 训练环境和推理环境分离。
- 推理进程独立运行，限制 CPU 线程数。
- 模型及阈值文件必须成对校验版本和哈希。
- 三图推理设置硬超时，超时统一转人工。
- 启动时先执行模型自检；自检失败不提供低风险候选。
- 记录模型版本、每图分数、整单结论、耗时和异常原因。
- 不使用网络 API，网络异常不影响本地检测。

## 10. 验收标准

### 第一版工程验收

- 数据校验可以发现重复、缺失、损坏和未确认标签。
- 训练、评估、ONNX 导出和三图推理命令可重复执行。
- PyTorch 与 ONNX 对同一输入的输出差异在预设容差内。
- 缺少模型、模型损坏、图片损坏和超时都返回 `manual_review`。
- 在当前电脑上测量三图 P50、P95 和最大耗时。

### 第一版效果说明

- 报告交叉验证和锁定集的实际结果，不预设准确率。
- 只要锁定非实拍测试集中出现漏放，报告必须明确记录。
- 即使锁定集零漏放，也只能说明当前小测试集结果，不能宣称生产零漏放。
- 第一版不得接入自动通过。

## 11. 增量训练

后续每次新增样本时：

1. 计算 SHA-256 并登记 `source_group`。
2. 人工确认标签后追加到新版本清单。
3. 保留所有旧挑战集，禁止只测试新样本。
4. 使用相同训练协议重新训练，不在旧权重上无限连续微调。
5. 比较旧模型和新模型的非实拍召回、实拍误转人工率及 CPU 耗时。
6. 只有新模型不降低安全指标且运行指标合格，才替换影子模型。

## 12. 本轮不做

- 不修改生产审核代码、提示词、阈值或配置。
- 不部署 YOLOX 或多模型级联。
- 不使用现有 100 张实拍候选的未清洗标签直接训练。
- 不把数字增强图片计为独立真实翻拍测试样本。
- 不承诺小样本模型达到正式上线标准。
