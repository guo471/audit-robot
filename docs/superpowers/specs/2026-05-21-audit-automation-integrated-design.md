# 嘉惠多多审核自动化整合方案设计

> 日期：2026-05-21  
> 范围：非发券 3C 与国补家电数码 3C 首期自动通过方案  
> 路线：影刀首期闭环验证，Playwright 保留可替换路线  
> 核心原则：只自动通过高置信合格单，不自动驳回；不确定即人工

## 1. 背景与目标

当前审核工作主要在网页审核后台完成。审核员每天重复打开订单、查看字段、打开图片、比对 SN 码、核验身份证姓名和有效期、判断商品图片是否为实拍。业务实际情况中，约 700 单里通常只有十几单不合格，因此项目价值不在于自动发现所有坏单，而在于安全地筛出绝对能通过的标准单，减少人工重复点击和重复比对。

现有项目已经具备初步的本地 OCR、SN/IMEI 提取、身份证解析、图像鉴伪、地址判断和规则引擎能力，但还没有完成网页自动化手脚层接入。当前设计目标是建立一套可验证、可替换、可复查的自动通过系统。

首期目标如下：

| 指标 | 目标 |
|---|---:|
| 单日订单量 | 700 单 |
| 自动驳回率 | 0% |
| 自动通过率 | 先试运行测真实基线，首期目标 70%-85% |
| 单单最大审核预算 | 60 秒 |
| 700 单耗时 | 首期优化后争取 2-4 小时 |
| 数据外传 | 0 |

当前硬约束必须保留在方案中：用户电脑为 i5-14400、16GB 内存、Intel UHD 730 集显，PaddlePaddle 为 CPU 版 3.2.0。没有可用 GPU，OCR 和图像判断速度存在上限，不能承诺稳定 700 单 1 小时内完成。

## 2. 首期业务边界

### 2.1 非发券 3C

非发券 3C 首期纳入自动通过范围。自动通过必须同时满足：

- 页面字段读取完整，嘉联订单号存在。
- 商品品类属于首期支持的 3C/手机/数码范围。
- 身份证人像面 OCR 姓名与页面姓名一致。
- 身份证国徽面 OCR 有效期未过期。
- 商品图或激活图中明确识别到页面 SN。
- 商品/激活相关图片无强非实拍、截图、网图、拼图、P 图风险。
- 服务执行未异常，单单耗时未超过 60 秒。

IMEI1/IMEI2 不作为首期自动通过硬条件。识别到且一致时可作为辅助证据；识别不到不阻断自动通过；如果识别到明显冲突，则转人工。

### 2.2 国补家电数码 3C

国补家电数码为交叉审核队列，点击下一条后可能从 3C 切到家电，也可能从家电切到 3C。因此每一单都必须重新读取页面字段，动态判断品类，不能沿用上一单类别。

国补首期规则：

- 不套用非发券身份证规则，因为国补页面通常没有身份证图片。
- 能效和发票不参与机器人自动判断，只记录字段状态。
- 每单根据类型、商品名称、品牌、规格型号等字段动态分类。
- 图片角色至少应能识别商品照片、拆封照片、SN 码采集/激活照片。
- SN 必须在相关图片中明确匹配页面 SN。
- 商品、拆封、SN 采集图片无强非实拍风险。
- 家电订单额外要求收货地址达到小范围粒度。

家电地址首期只自动通过明显细地址，例如小区、路号、栋、单元、室、门牌、村组等。仅到省、市、区县、乡镇、街道，或只到村但无组/门牌的地址，进入人工。

### 2.3 首期不自动通过的场景

以下情况统一返回 `manual`，手脚层点击下一条：

- 页面字段读取不完整。
- 图片标题或图片角色无法判断。
- SN 未识别、疑似不一致或置信不足。
- 身份证姓名或有效期无法高置信识别。
- 商品图片存在截图、网图、拼图、P 图、非实拍强风险。
- 家电地址处于灰区。
- 历史驳回后重新提交、疑似资料篡改。
- 汽车审核。
- 服务异常或单单耗时超过 60 秒。

## 3. 总体路线

采用“影刀首期闭环验证，Playwright 保留替代路线”的方案。

推荐原因：

- 影刀更适合首期快速完成网页字段采集、图片下载和按钮点击。
- 本地审核服务负责全部判断逻辑，影刀只做手脚，不承载业务规则。
- 通过统一 JSON 接口隔离手脚层，后续可以从影刀迁移到 Playwright。
- n8n 不适合做网页审核操作，后期可用于日报、通知、调度。
- Dify/扣子不进入生产审核链路，避免敏感图片、身份证、订单数据外传；后期只能用于脱敏知识库或人工辅助问答。

## 4. 系统架构

```text
网页审核后台
  |
  | 读取字段、图片标题、图片链接
  v
手脚层：影刀首期 / Playwright 备选
  |
  | 下载图片到本地临时目录
  | 调用本机审核服务
  v
本地审核服务 127.0.0.1:8765
  |
  | 场景识别
  | 品类动态分类
  | 图片角色判断
  | OCR / SN / 身份证 / 地址 / 实拍风险
  | 快路径 / 慢路径 / 60 秒超时
  v
返回 pass / manual / error
  |
  +-- pass   -> 手脚层点击通过
  +-- manual -> 手脚层点击下一条
  +-- error  -> 按配置暂停或下一条
```

本地服务必须绑定 `127.0.0.1`，禁止监听 `0.0.0.0`。接口需要 token，避免本机其他进程随意调用。图片只下载到本地临时目录，用完删除。

## 5. 数据流与接口边界

手脚层向本地服务传入统一 JSON：

```json
{
  "jl_order_no": "嘉联订单号",
  "channel_order_no": "渠道订单号",
  "scene_hint": "页面活动或路径",
  "fields": {
    "name": "姓名",
    "product_type": "类型",
    "product_name": "商品名称",
    "brand": "品牌",
    "model": "规格型号",
    "sn": "SN码",
    "imei1": "IMEI1",
    "imei2": "IMEI2",
    "merchant": "所在商户",
    "delivery_method": "配送方式",
    "address": "收货地址"
  },
  "images": [
    {
      "title": "页面图片标题",
      "path": "本地临时图片路径"
    }
  ]
}
```

本地服务返回：

```json
{
  "decision": "pass",
  "action": "approve",
  "jl_order_no": "嘉联订单号",
  "scene": "guobu_3c",
  "path": "fast",
  "elapsed_sec": 18.6,
  "manual_reason": null,
  "evidence": {
    "sn_match": true,
    "image_roles_ok": true,
    "real_photo_pass": true,
    "id_name_match": null,
    "id_valid": null,
    "address_detail_ok": null
  }
}
```

当不满足自动通过条件时返回：

```json
{
  "decision": "manual",
  "action": "next",
  "jl_order_no": "嘉联订单号",
  "scene": "guobu_home_appliance",
  "path": "slow",
  "elapsed_sec": 60.0,
  "manual_reason": "SN未高置信识别或单单超时"
}
```

系统内部可保留 `skip` 兼容旧规则，但对外统一表达为 `manual`，避免语义误解。

## 6. 审核策略

### 6.1 证据链自动通过

自动通过必须依赖证据链，而不是单点判断。证据链包括：

- 页面字段完整。
- 场景和品类分类明确。
- 图片标题能映射到预期角色。
- SN 明确匹配。
- 商品相关图片无强风险。
- 非发券 3C 的身份证姓名和有效期明确通过。
- 家电地址达到足够细粒度。
- 未触发异常、冲突或超时。

任何关键证据不稳定，均返回 `manual`。

### 6.2 图片角色分类

不能按图片顺序硬判断。首期优先使用页面图片标题判断：

| 标题特征 | 角色 |
|---|---|
| 身份证人像面 | `id_front` |
| 身份证国徽面 | `id_back` |
| 新物照片/商品照片 | `product_photo` |
| 拆封照片 | `unboxing_photo` |
| 激活照片/SN码采集/序列号 | `activation_photo` |
| 无法识别 | `unknown` |

如果同一标题上传多张图片，不能按顺序强配。处理方式是同一角色允许多图，每张图分别 OCR 和风险判断，再汇总角色级证据。例如多个“商品照片”中，只要其中一张提供 SN/品牌/型号辅助证据，且所有商品相关图无强风险，才可继续；如果多图互相冲突或重复异常，转人工。

### 6.3 OCR 无法理解商品的问题

OCR 只能识别文字，不能真正理解“这是商品还是包装”。首期不引入通用多模态模型作为主链路，因为当前电脑没有 GPU，CPU 跑视觉语言模型速度不可接受，且敏感图片外传不可接受。

现实方案是使用组合证据：

- 页面标题提供图片角色。
- 页面品类、商品名、品牌、型号提供上下文。
- 图片 OCR 识别 SN、品牌、型号、条码文字等证据。
- 图片实拍风险检测过滤截图、网图、拼图、P 图等强异常。
- 图片重复检测和冲突检测发现明显异常。

这个方案不能完全理解图片内容，但可以覆盖大量标准单。无法高置信的订单进入人工。

## 7. 性能分层

### 7.1 快路径

快路径用于标准单，目标耗时 10-25 秒/单。进入条件：

- 页面字段完整。
- 图片标题明确。
- 优先图片中增强 OCR 一次命中 SN。
- 非发券 3C 的身份证姓名和有效期一次识别成功。
- 商品相关图无明显强风险。
- 未出现字段冲突。

快路径是首期效率的关键。实际能否达到 2-4 小时处理 700 单，取决于快路径占比。

### 7.2 慢路径

慢路径只处理仍有希望自动通过的订单，目标耗时 40-90 秒/单。触发条件：

- SN 小字未命中但图片角色明确。
- 身份证有效期需要二次识别。
- 激活图未命中但商品图或拆封图可能包含 SN。
- 图片质量一般但未触发强风险。

慢路径不能无边界扩张。分块 OCR、增强 OCR、多图补扫必须有范围限制。

### 7.3 60 秒超时

首期单单最大审核预算为 60 秒。超过 60 秒仍没有高置信结论，立即返回 `manual`。这会牺牲一部分自动通过率，但能防止少量难单拖慢全天效率。

## 8. 日志、报表与安全

日志和报表保留：

- 嘉联订单号。
- 渠道订单号，如有必要。
- 场景分类。
- 品类分类。
- 决策结果。
- 快路径或慢路径。
- 耗时。
- 转人工原因码。
- 关键证据布尔值，例如 SN 是否匹配、身份证是否通过、地址是否足够细。

日志和报表禁止保存：

- 身份证号。
- 手机号。
- 图片 URL。
- 原始图片。
- OCR 原文全文。
- 完整地址明文。

地址可记录粗粒度判断结果，例如 `address_detail_ok=true/false`，不记录完整地址。临时图片处理结束后删除。若为排查问题需要保留样本，必须手工脱敏并单独存放，不进入默认日志链路。

## 9. 实施阶段

### 阶段 0：安全与基线

补齐脱敏日志、CSV 报表、嘉联订单号、耗时统计、转人工原因、场景类型、快慢路径标记。先让系统可度量，再谈优化。

预期产出：每天能看到处理量、平均耗时、SN 未命中原因、图片风险原因、超时数量、自动通过率。

### 阶段 1：本地审核服务

将现有命令行引擎改为常驻本地服务，绑定 `127.0.0.1`，增加 token、统一 JSON 输入输出、临时文件清理、60 秒超时。

预期产出：影刀和 Playwright 都可调用同一服务，避免业务逻辑绑定某个手脚工具。

### 阶段 2：影刀最小闭环

影刀只负责读取字段、采集图片标题和链接、下载图片、调用本地服务、按结果点击通过或下一条。先运行观察模式，再启用自动通过。

预期产出：完成真实网页端到端验证，确认影刀稳定性、费用、安全配置和页面字段采集可靠性。

### 阶段 3：试运行与调优

连续试运行不少于 3 天。每天查看报表，抽查自动通过订单。出现误通过立即收紧规则；转人工过多时定位具体原因。

预期产出：得到真实通过率、耗时分布、常见转人工原因，为后续优化提供依据。

### 阶段 4：效率优化与备选迁移

如果影刀稳定且成本可接受，继续优化快路径。如果影刀收费、安全或稳定性不能满足要求，则切换到 Playwright。n8n 后期接日报、通知、调度；Dify/扣子仅用于脱敏知识库。

预期产出：700 单处理耗时逐步压到 2-4 小时区间，并判断是否有机会进一步接近 1.5-3 小时。

## 10. 开发成本估算

| 模块 | 预计工期 |
|---|---:|
| 脱敏日志、CSV 报表、嘉联订单号、耗时统计 | 0.5-1 天 |
| 本地审核服务接口、token、临时文件清理 | 1-2 天 |
| 快路径、慢路径、60 秒超时策略 | 1-2 天 |
| 图片标题采集与角色分类规则 | 1 天 |
| 国补 3C/家电动态分类与地址规则 | 1-2 天 |
| 影刀最小闭环联调 | 1-3 天 |
| 试运行报表分析与规则调优 | 3-7 天 |
| Playwright 备选验证 | 2-4 天，可后置 |

首期可用版本预计 5-10 个工作日。稳定优化到可长期使用的生产辅助工具预计 2-4 周。实际工期受网页字段采集难度、影刀联调、图片标题稳定性和真实数据质量影响。

运行成本：

- 本地 Python 引擎：基本 0 元。
- 影刀：费用需按账号和授权确认，不能假设免费。
- Playwright：工具免费，但开发成本更高。
- n8n：自建可免费，云版收费；首期不放主链路。
- Dify/扣子：不建议进入生产审核链路，避免敏感数据外传。
- 多模态大模型看图：首期不建议。云模型有数据安全风险，本地 CPU 跑不动，本地 GPU 方案需要额外硬件投入。

## 11. 主要风险与处理

### 11.1 速度风险

风险：当前 CPU OCR 慢，分块 OCR 会显著拉长单单耗时。

处理：快路径优先、慢路径限范围、60 秒超时、报表统计耗时分布。不能承诺现有机器稳定 700 单 1 小时内完成。

### 11.2 误通过风险

风险：自动通过错误会造成业务风险。

处理：只自动通过证据链完整的订单；发现误通过立即收紧规则；首期不自动驳回。

### 11.3 图片内容理解风险

风险：OCR 无法真正理解商品和包装关系。

处理：用标题角色、SN、品牌型号文字、实拍风险、重复检测、冲突检测组合判断。无法高置信时转人工。

### 11.4 家电地址灰区

风险：地址合规有解释空间，规则不能覆盖所有情况。

处理：只自动通过明显细地址；灰区转人工；通过报表统计常见灰区后再决定是否扩展规则。

### 11.5 影刀集成风险

风险：影刀尚未完整联调，字段采集、JSON 解析、异常处理、点击稳定性都有未知数。

处理：首期做最小闭环；影刀只做手脚；本地服务接口稳定；保留 Playwright 替代路线。

### 11.6 数据安全风险

风险：订单、身份证、图片、SN 属于敏感信息。

处理：不上传第三方 API；服务只监听 `127.0.0.1`；接口加 token；临时图片用后删除；日志脱敏；默认不保存 OCR 原文和图片 URL。

## 12. 基于现有项目的修改建议

建议新增模块：

- `audit_service.py`：本地 HTTP 服务入口。
- `modules/audit_models.py`：统一请求和响应结构。
- `modules/image_role.py`：按标题和辅助证据判断图片角色。
- `modules/category_classifier.py`：区分非发券 3C、国补 3C、国补家电、其他。
- `modules/privacy.py`：脱敏、临时文件清理、日志字段过滤。
- `modules/report_writer.py`：CSV/Excel 报表输出。

建议修改模块：

- `run_audit.py`：拆出可复用审核函数，保留命令行兼容。
- `modules/ocr_engine.py`：增加快路径 OCR 和慢路径补扫策略。
- `modules/rule_engine.py`：对外统一 `manual` 语义，保留 `skip` 兼容字段。
- `modules/image_forensics.py`：输出风险等级和原因码，避免一刀切。
- `modules/address_checker.py`：增加家电地址细粒度规则。
- `config.py`：增加超时、token、日志脱敏、快慢路径开关。

## 13. 验收标准

首期验收标准：

- 自动驳回率为 0。
- 自动通过订单抽查无明显误通过。
- 日志可按嘉联订单号复查。
- 单单最大审核预算 60 秒内可控退出。
- 报表能统计通过率、耗时、快慢路径占比、转人工原因。
- 自动通过率最低验收线建议不低于 60%，目标线为 70%-85%。
- 700 单在首期优化后争取 2-4 小时完成；若真实数据无法达到，需要根据报表决定是优化引擎、增加硬件、调整规则，还是缩小自动化范围。

## 14. 暂不解决的问题
