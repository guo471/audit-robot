# 国补订单采集字段核对清单

> 用途：打开一单真实国补订单详情页时，逐项确认采集器需要读取哪些字段、字段在页面哪里、图片如何下载，以及采错时如何停止。  
> 原则：只采集，不点击通过，不点击驳回，不修改订单状态。

## 1. 单页核对流程

每次先用 1 单真实订单验证，不要直接批量跑。

1. 打开订单详情页。
2. 确认页面已完全加载。
3. 记录当前订单的渠道订单号。
4. 按本清单逐项核对字段。
5. 下载或打开图片，确认图片和订单对应。
6. 生成本地任务 JSON。
7. 人工对照页面和 JSON，确认没有字段错位。
8. 连续 20 单无错位后，再考虑小批量采集。

## 2. 必采字段

| 字段 | 是否必采 | 页面核对方式 | 采集失败处理 |
|---|---|---|---|
| 渠道订单号 | 必须 | 页面订单信息区域，应唯一对应当前订单 | 停止采集，标记 `FIELD_MISSING` |
| 场景/活动名称 | 建议 | 页面标题、活动路径或活动名称 | 缺失时默认 `guobu`，但记录 |
| 商品类型/品类 | 必须 | 如手机、电脑、电视、冰箱等 | 标记 `FIELD_MISSING` |
| 系统 SN | 必须 | 页面录入的 SN/SN码/序列号字段 | 标记 `SYSTEM_SN_MISSING` |
| 收货地址 | 条件必采 | 仅商品类型属于家电时采集；数码/3C 不采也不阻断 | 家电订单缺失则标记 `FIELD_MISSING` |
| 页面感叹号/异常提示 | 必须 | 订单字段或图片旁若出现感叹号、异常标记、风险提示 | 直接转人工，原因 `PAGE_WARNING_FLAG` |

首期不采集或不作为判断依据：

- 商品名称
- 品牌
- 规格型号
- 价格
- 补贴金额
- 商品条码
- 能效标识
- 发票编号
- 发票照片
- IMEI1/IMEI2

## 3. 必采图片信息

首期只采集三张业务图片：

1. 商品照片
2. 拆封照片
3. SN码采集 / 激活照片

图片审核要求：

| 场景 | 图片 | 合格要求 | 不满足时 |
|---|---|---|---|
| 全部 | 商品照片 | 需要体现商品本体，且商品品类必须和页面商品类型一致，例如手机订单不能上传平板照片 | 转人工 |
| 家电 | 拆封照片 | 按整组拆封/安装照片判断，不要求每一张拆封图都同时出现包装和商品；只要整组里至少一张有包装和商品合照，或结合商品照能形成完整证据链，即可合规 | 证据链不足才转人工 |
| 数码3C | 激活照片 | 必须是对应品类商品亮屏显示激活码，并与盒子条码页/SN页同框 | 转人工 |
| 数码3C | 激活照片只有 1 码或 2 码 | 允许结合盒子上的 SN 码综合比对 | SN 仍无法一致则转人工 |

每张图片至少采集：

| 字段 | 是否必采 | 说明 |
|---|---|---|
| 图片标题 | 必须 | 例如商品照片、拆封照片、SN码采集照片、激活照片 |
| 图片链接或下载方式 | 必须 | 能下载到本地即可 |
| 本地图片路径 | 必须 | 下载后写入任务 JSON |
| 图片顺序 | 禁止依赖 | 不能按第 1/2/3 张图绑定角色。必须按页面标题分组采集，同一标题下允许多张图 |

图片相关停止条件：

| 情况 | 处理 |
|---|---|
| 图片下载失败 | 当前订单转人工，原因 `IMAGE_DOWNLOAD_FAILED` |
| 图片标题为空 | 当前订单转人工，原因 `IMAGE_MISSING` 或 `FIELD_MISSING` |
| 任一核心标题分组缺失 | 当前订单转人工，原因 `IMAGE_MISSING` |
| 图片和订单明显不对应 | 停止批量采集，人工检查页面定位 |
| 同一张图重复下载到多个订单 | 停止批量采集 |

## 5. 小批量采集规则

建议分阶段：

| 阶段 | 单量 | 目标 |
|---|---:|---|
| 手动核对 | 1 单 | 确认字段位置 |
| 连续核对 | 5 单 | 看字段是否稳定 |
| 小批量 | 20 单 | 看是否会错位、漏图、重复 |
| 试跑 | 100-200 单/天 | 形成真实判断表 |

小批量期间必须抽查：

- 渠道订单号是否和页面一致。
- 系统 SN 是否和页面一致。
- 商品类型是否和页面一致。
- 家电订单是否采到地址，数码订单是否允许地址为空。
- 图片是否属于当前订单。
- 图片是否按页面标题分组，对应商品照片、拆封照片、SN码采集 / 激活照片。
- 同一标题下如果有多张图片，是否全部采集，不能只取第一张或固定前三张。
- SN 码采集 / 激活照片分组下有几张图，后续 SN 检测就必须传几张图逐一比对。
- 家电拆封/安装照片按整组判断，不逐张要求包装和商品同框；整组至少一张有包装和商品合照即可。
- 判断表里的订单数量是否等于采集订单数量。

## 6. 自动停止条件

采集器遇到以下情况必须停止，不允许继续批量跑：

| 停止条件 | 原因 |
|---|---|
| 渠道订单号为空 | 主键缺失，无法复核 |
| 连续 2 单系统 SN 为空 | 可能字段选择器失效 |
| 商品类型为空 | 无法判断是否需要地址 |
| 家电订单收货地址为空 | 家电条件字段缺失 |
| 页面字段或图片旁有感叹号 | 页面已有异常提示，直接转人工 |
| 核心标题分组缺失或分组下图片为空 | 无法形成模型判断输入 |
| 图片下载失败率超过 10% | 页面或权限可能异常 |
| 出现重复渠道订单号 | 可能页面没有切换成功 |
| 下一单加载超时 | 可能登录失效或页面卡住 |
| 页面出现验证码 | 需要人工处理 |
| 字段内容明显错位 | 继续跑会污染样本 |

## 8. 判断采集插件是否稳定

插件或浏览器自动化工具可以认为“基本稳定”的标准：

1. 连续 20 单字段无错位。
2. 连续 20 单图片均能下载并对应正确订单。
3. 渠道订单号无重复。
4. 系统 SN 无异常缺失。
5. 登录态至少能支撑一次 20 单小批量。
6. 失败时能停止，而不是继续采集错误数据。

如果达不到这些标准，先不要批量采集 100-200 单。

## 9. 影子审核输出表

影子审核完成后输出表格至少包含：

| 字段 | 说明 |
|---|---|
| ID | 渠道订单号或任务ID，优先使用渠道订单号 |
| 是否转人工 | 是/否 |
| 转人工原因 | 标准原因码 + 简短中文说明 |
| 判断用时 | 单单模型与规则判断耗时 |

新增原因码：

| 原因码 | 中文说明 |
|---|---|
| `PAGE_WARNING_FLAG` | 页面旁边存在感叹号或异常提示 |
| `ADDRESS_TOO_COARSE` | 家电地址不够精确 |
| `PRODUCT_PHOTO_INVALID` | 商品照片未体现商品 |
| `PRODUCT_TYPE_MISMATCH` | 图片中商品品类与页面商品类型不一致 |
| `UNBOXING_PHOTO_INVALID` | 家电拆封照片不是盒子和商品合照 |
| `ACTIVATION_PHOTO_INVALID` | 数码3C激活照片不符合亮屏激活码与盒子条码页同框要求 |
