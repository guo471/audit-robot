## 项目目标与边界

- 以影子审核方式输出判断表格，不修改后台订单状态。
- 优先避免误放高风险订单，同时控制正常订单误转人工率。
- 最终 Excel 包含明细表和汇总表，明细至少保留订单号、是否转人工、原因码及原因、系统 SN、模型 SN、原流程状态、耗时和 token。
- 接口地址和 API key 只注入当前进程环境变量，不写入代码、文档、日志或报表。

采集完成的硬性条件：

- 任务数等于请求数。
- `detailErrorOrders=0`。
- `missingRequiredPhotoGroupOrders=0`。
- 商品、拆封、激活/SN 三组均非空。
- 下载错误为 0，任务中所有本地图片实际存在。
- 任务结构校验全部通过。

禁止事项：

- 不得只用列表接口生成审核任务。
- 不得按页面 DOM 顺序、第一张、中间张或最后一张推断图片角色。

- 缺任一照片组时不得启动正式审核。

## 唯一现行审核规则

审核入口：`tools/run_guobu_model_audit_v2.py`。

固定配置：

- 模型：`qwen3.7-plus`。
- 模式：`hybrid`。
- `workers=1`，关闭 targeted SN review。
- 千问所有阶段固定 `enable_thinking=false`。
- 单单异常不终止整批；批次结束后只补跑超时、连接失败和 HTTP 500 服务异常单一次。

审核链路：

1. 本地预检字段、系统 SN、家电地址和照片组完整性。
2. SN 阶段只读取明确的激活/SN照片组。
3. SN 通过后，商品、拆封、激活/SN 三组的所有照片都进入合规检测。
4. 最终按订单号合并首轮和补跑结果，生成 Excel 明细表和汇总表。

## 当前业务口径

- SN 本地严格比较，规范化后必须完全一致，不使用 O/0、B/8 等视觉容错自动放行。
- SN 候选保留证据来源；设备屏幕明确展示的 SN 与系统 SN 冲突时，即使包装 SN 一致也转人工。
- IMEI 不参与系统 SN 冲突比较。
- 智能手表/手环的配对页、设置页和设备名称页不是 SN/序列号身份凭证；屏幕无身份信息时，包装 SN 不能替代。
- 家电拆封证据必须展示可识别外包装。
- 地址到编号组视为粒度合格，例如 `一组`、`1组`；订单仍继续经过后续 SN 和图片规则。
- 家电地址包含 `商贸`、`京东家电`、`楼` 任一关键词时视为粒度合格；仅放行地址预检，仍继续 SN 和全部照片审核。
- 允许其中两组照片重复；只有商品、拆封、激活三组全部为同一张图片才以 `DUPLICATE_IMAGE_EVIDENCE` 转人工。
- 照片真实性规则仍按现行提示词处理；未明确授权时不新增模型调用。
- 家电拆封/安装证据链严格口径：拆封/安装照片组自身必须看到商品本体；有包装时必须同时看到商品本体和包装/外箱/拆封关系，不能只有纸箱、箱体内部、泡沫、塑料袋、标签或说明书；无包装时必须看到商品本体已经到家、安装、摆放或处于使用场景。不得用商品照片中的商品本体去补拆封/安装照片缺失的商品本体。

## FFT关闭决策（2026-07-15）

- 已确认多张正常实拍在模型无任何强弱证据、文字也判断实拍时，被FFT高分误转人工。

- 3C屏幕没有SN、仅显示IMEI1/IMEI2时，包装SN才作为系统SN比较的备用来源。
- 屏幕既无SN也无IMEI1/IMEI2时，不允许仅凭包装SN自动通过。
- 模型输出的`normalized_text`不得覆盖原始读取值；应从标签绑定后的`raw_text`由本地生成裁决值。
- 只有同一有效优先级内两个明确、完整且不同的SN才属于候选冲突。

计划修改范围：

1. 微调SN主提示词：移除“条形码下方数字天然等同SN”，增加品类分支、`screen_identity_state`、图片来源和SN标签绑定要求；原因码保持英文固定值，`manual_reason`用一句中文解释。
2. 微调本地SN裁决：改为按品类分支的锁定式状态机，落实家电单SN、3C屏幕优先、IMEI页面包装回退；低优先级候选无否决权。
3. 本地从原始值生成候选规范值，模型`normalized_text`仅作为诊断信息；不全局修改`normalize_sn()`。
4. 插件2保持关闭，不新增常规模型调用，不改变60秒超时。
5. 图片真实性、地址、激活合规、拆封/安装、重复照片、品类和报表规则禁止改动。

验证要求：

- 建立24条SN逻辑回归用例，覆盖候选顺序反转和6类非SN隔离护栏。
- 回放最近9个相关生产订单；已确认的6个第二候选误拦不得再出现`SN_MISMATCH`。
- 真正的屏幕SN不一致、包装SN匹配场景必须继续100%拦截。
- 全量现有测试连续3次通过，非SN字段和原因码结果零变化，插件2无调用记录。
- 正式上线前执行至少150次关键实图重复验证，并对100至200单进行影子审核。

待确认边界：家电机身和包装都明确显示SN但两个值不一致时，专家建议使用`MODEL_UNCERTAIN`转人工。

### SN标签真实性插件默认关闭与删除待办（2026-07-21）

当前决定：`SN标签真实性插件`保持默认关闭。常规审核不得自动添加`-EnableSnLabelAuthReview`，并须在启动前显式设置`SN_LABEL_AUTH_REVIEW_MODE=off`，避免复用终端中残留的`on`值；只有用户明确要求单独受控实验时才允许开启，并且实验组与对照组只能改变这一个开关。

本次教训与证据：

- 冰箱订单`481172181730682663731257`在旧运行和插件关闭的受控复跑中均通过；开启插件后，模型把`img_004`标记为`LOCAL_MOIRE(product_body)`，随后被主线R9转人工。关闭插件后的受控复跑在`25.07s`内通过，结果见`reports/model_audit/fridge_control_snlabel_off_20260721_combined.json`。

- 单变量实验必须先核对运行manifest及开关状态；验证某一插件时，其他无关插件必须保持项目默认值。不得把多个开关同时变化后的结果归因于其中一个改动。
- 审核Skill曾在常规命令中错误要求显式开启该插件，造成无关规则污染；该操作指引已改为默认关闭，并在常规运行前显式清除残留开启状态。项目代码、项目流程文档在环境变量未设置时原本已是默认关闭，当前不修改主线代码。
