## 项目目标与边界

- 以影子审核方式输出判断表格，不修改后台订单状态。
- 优先避免误放高风险订单，同时控制正常订单误转人工率。
- 最终 Excel 包含明细表和汇总表，明细至少保留订单号、是否转人工、原因码及原因、系统 SN、模型 SN、原流程状态、耗时和 token。
- 接口地址和 API key 只注入当前进程环境变量，不写入代码、文档、日志或报表。

- 下载错误为 0，任务中所有本地图片实际存在。
- 任务结构校验全部通过。

禁止事项：

- 缺任一照片组时不得启动正式审核。

## 唯一现行审核规则

审核入口：`tools/run_guobu_model_audit_v2.py`。

固定配置：

- 模型：`qwen3.7-plus`。
- 模式：`hybrid`。
- `workers=1`，关闭 targeted SN review。
- 千问所有阶段固定 `enable_thinking=false`。
- 单单异常不终止整批；批次结束后只补跑超时、连接失败和 HTTP 500 服务异常单一次。

审核链路：

1. 本地预检字段、系统 SN、家电地址和照片组完整性。
2. SN 阶段只读取明确的激活/SN照片组。
3. SN 通过后，商品、拆封、激活/SN 三组的所有照片都进入合规检测。
4. 最终按订单号合并首轮和补跑结果，生成 Excel 明细表和汇总表。

## 当前业务口径

- SN 本地严格比较，规范化后必须完全一致，不使用 O/0、B/8 等视觉容错自动放行。
- SN 候选保留证据来源；设备屏幕明确展示的 SN 与系统 SN 冲突时，即使包装 SN 一致也转人工。
- IMEI 不参与系统 SN 冲突比较。
- 智能手表/手环的配对页、设置页和设备名称页不是 SN/序列号身份凭证；屏幕无身份信息时，包装 SN 不能替代。
- 家电拆封证据必须展示可识别外包装。
- 地址到编号组视为粒度合格，例如 `一组`、`1组`；订单仍继续经过后续 SN 和图片规则。
- 家电地址包含 `商贸`、`京东家电`、`楼` 任一关键词时视为粒度合格；仅放行地址预检，仍继续 SN 和全部照片审核。
- 允许其中两组照片重复；只有商品、拆封、激活三组全部为同一张图片才以 `DUPLICATE_IMAGE_EVIDENCE` 转人工。
- 照片真实性规则仍按现行提示词处理；未明确授权时不新增模型调用。

## 照片真实性专项成果（2026-07-15）

专项目标是单张判断图片是否为直接实拍，还是对屏幕、相片、打印物或其他图像载体的二次拍摄。该能力当前在隔离分支完成验证，尚未自动并入 `tools/run_guobu_model_audit_v2.py` 主线；正式接入前需明确授权并完成接口集成。

- 分支：`codex/non-real-photo-agent-v1`
- 最终报告：`.superpowers/sdd/task-10-final-validation-report.md`
- 关键提交：`400382f`、`c22533c`、`adcdd49`、`d3491b3`、`2d29ec6`

冻结方案：

1. 使用 V4 单全图提示词审查可见二次载体证据。
2. 提示词优先检查外部载体/嵌套边界、四边异常、跨对象摩尔纹、外部界面归属和外层光学平面。
3. 商品自身屏幕内的界面、局部摩尔纹和普通反射不得单独作为外部屏摄强证据。
4. V4 无证据时，使用只读取解码 RGB 像素的 FFT 分类器补救。
5. FFT 固定阈值 `0.995`，只能执行 `no_evidence -> manual_review`，不得新增 high，也不得修改 V4 已有 high/manual。
6. FFT 本地执行最多尝试两次，仍失败则 fail-closed 转人工。
7. 模型为 `qwen3.7-plus`，所有调用固定 `enable_thinking=false`。

冻结标识：

- V4 提示词：`photo_authenticity/prompts/non_real_photo_auditor_v4.txt`
- FFT extractor：`fft-v1-512-ycbcr-5x53`，795维像素频域特征。
- FFT 模型 SHA-256：`49352975e2ef36d3723cbe6fe028687a56101920fef50becc744c65b96aa512b`
- FFT artifact：`reports/non_real_photo_classifier/dev100-v1/frozen_fft_v2_threshold995`
- 最终阈值：`0.995`

样本与验证：

- 用户确认非实拍394张、实拍385张，共779张物理图片。
- 固定开发批：100非实拍+100实拍，按 group+SHA 传递组件隔离。
- 第一验证批发现阈值过宽：非实拍高召回，但实拍干预9/100，因此正式判失败。
- 阈值只调整为0.995，模型、提示词和特征不变。
- 第二独立100+100验证批：非实拍95/100，实拍干预6/100，执行失败0；两位独立专家均 `APPROVED`。
- 全部剩余179张也已运行，不抽样、不拆组件。
- 全库统一0.995语义口径：非实拍364/394（92.39%），实拍干预20/385（5.19%）。
- 若计入两张非实拍执行失败后的安全转人工，生产路由为366/394（92.89%）。
- 最后困难尾部批为81/94（86.17%），必须保留该限制，不能宣称每个子批次均超过90%。

性能与成本：

- V4通常约5.3秒/张。
- FFT验证P50约0.45至0.97秒/张，P95约1.21至1.44秒/张。
- 已记录总模型使用量约2,376,675 tokens；未冻结价格表，因此不报告货币成本。

业务结论：

- 以总体口径达到“非实拍拦截至少90%、实拍干预不超过6%”验收线。
- 当前779张均已消费为开发或验证证据，不得继续调参后将这些图片称为盲测。
- 后续若继续优化，应对 FFT 分数 `[0.95, 0.995)` 的图片增加局部语义复核，只在明确指出同方向、同间距纹理跨越两个物理区域时转人工，并使用全新外部样本验证。
- 禁止直接把FFT阈值降至0.90或0.95；这会使全库实拍干预超过业务线。
- API地址和密钥仍只保存在用户环境变量中，不得写入文档、代码、日志或报告；现有密钥建议轮换。
